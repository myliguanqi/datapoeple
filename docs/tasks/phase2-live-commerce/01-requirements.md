# 01 需求清单

每条需求带编号，实现与测试都要能对上编号。"验收"是该需求完成的判定标准。

## R1 弹幕接入：尽可能拿到直播间与用户的全部信息

- 把 `D:\jobdemo\douyin_zhibo\vendor\douyin_fetcher` 整个目录复制到本仓库 `vendor/douyin_fetcher/`（保留 LICENSE、README，源码不改）。
- 参考 `douyin_zhibo/danmaku/danmaku_source.py` 写适配层，把协议消息转成**统一事件模型**（见 03 §3），尽可能提取所有字段：
  - 用户：user_id / short_id / display_id / sec_uid、昵称、**性别**、头像、**财富等级 pay_grade（等级/名称/累计钻石/升级进度）**、
    **粉丝团（团名/等级/状态）**、用户等级、关注/粉丝数、徽章、是否认证、年龄段（有则取）、本场消费 `user_consume_in_room`、本场送礼次数。
  - 事件：弹幕、表情弹幕、礼物（礼物名/ID/单价钻石/连击数/组数/总数/连击结束标记/收礼人）、点赞（本次/累计）、进场、关注、分享、
    粉丝团加入/升级、在线人数/人气/累计观看、贡献榜、直播间统计、下播、商品变更（带货房间才有，需实测）。
  - 未适配的新消息类型：记一条"首次出现"日志并可开启裸解探针（沿用参考项目的 `_SNIFF` 思路）。
  完整字段表见 02 §3。
- 连击礼物去重（同一连击会多次推送，按连击结束或组 ID 结算，避免重复感谢、重复累计；⚠ 需实测确认推送规律）。
- 断线自动重连；房间号在 Web 上修改后热切换；登录 cookie 支持（收礼物必需）。
- 弹幕抓取运行在**独立子进程**，崩溃不影响直播主进程。
- 提供 **mock 弹幕源**（可配置事件频率、礼物比例、性别比例、财富等级分布）和 **JSONL 录制/回放**，无直播间也能开发测试。

**验收**：mock 源下，Web「弹幕互动」面板实时显示事件流，用户标签含性别/财富等级/粉丝团等级；
真实直播间（用户确认后）能收到 chat/gift/member/follow/like/room_stat；改房间号后 10 秒内切到新房间；杀掉弹幕子进程后自动拉起。

## R2 互动处理：参考 douyin_zhibo 的导演层

移植参考项目"平台层"互动逻辑（不要游戏层），改成带货直播语境：
- 事件保鲜窗口、本场回头客识别、本场礼物榜（守擂）、贡献榜点名（来自 `state_merger.py`）。
- 信号派生 + 触发器表（YAML 驱动：when / priority / cooldown / emotion / directive / 兜底话术）、能量与发声节流、同拍合并、
  礼物 S/M/L 分档、连续送礼、礼物后回踩维护、榜一易主、欢迎分级（金主回归/高财富等级/熟客/回头客/普通进场）、关注感谢、点赞汇总、
  人数猛涨/下滑、冷场点名、空闲话术（来自 `director.py` + `triggers.yaml`）。
- 跨场长期记忆：建档门槛（发言/送礼/关注才入库）、`known_before` 判定（来自 `user_store.py`）。
- 单槽优先级队列 + 过期丢弃（来自 `live_main.CueQueue`）。
- 按性别称呼（大哥/大姐）、昵称简称（来自 `director._honor_by_gender / _short_name`）。
- 新增带货语境信号：**产品提问**（问价格/规格/怎么买/发货/售后等）→ 知识库回答；**购买意向**；**讲品轮播**（空闲时讲当前产品）。
- 每类互动可在 Web 上开关、调优先级/冷却/阈值/话术模板（热更新）。

**验收**：用 mock 源注入"大礼物 + 高等级进场 + 产品提问 + 普通弹幕 + 点赞"混合序列，回复顺序符合优先级，过期的不播，
冷却内不重复；关掉某类互动后不再触发；决策日志可在 Web 查看（哪个事件 → 哪个触发器 → 说了什么）。

## R3 TTS：火山引擎（照抄参考项目实现）

- 移植 `douyin_zhibo/expression/tts_client.py`（V3 HTTP SSE 声音复刻）为本项目的 `TTSEngine` 实现，凭证从 `.env` 读取。
- 移植 `expression/tts_cache.py` 合成缓存（装饰器，任意 TTS 后端可用；缓存键含音色/语速/文本）。
- 语速可调（映射 V3 `speech_rate`）；音色、语速、资源 ID 可在 Web 设置（热更新）。
- 凭证缺失时按配置回退（edge → mock），并在 Web 显示"TTS 未配置"。

**验收**：mock HTTP 下单元测试覆盖 SSE 解析（含错误码、空音频）；用户同意后手动自测命令能合成一句并在数字人上播出；重复句命中缓存不再请求。

## R4 LLM：预留接口，读 .env

- OpenAI 兼容 `/chat/completions`，`.env` 提供 `LLM_API_URL`、`LLM_API_KEY`、`LLM_MODEL`（可选 `LLM_TIMEOUT` 等）。
- 接口支持非流式与流式（按句推给 TTS 以降低首句延迟）；超时/失败时回退到模板话术，不冷场。
- 温度、最大字数、人设提示词等在 Web 设置（热更新）；`.env` 改了可在 Web 点"重新加载 .env"。

**验收**：无 key 时系统正常运行（全部走模板）；mock LLM 下流式按句播报；Web 显示 LLM 是否可用、最近调用耗时与失败次数。

## R5 产品知识库：基于 html/pdf/md 文档回复与介绍

- 文档上传（Web）→ 解析（html/pdf/md，保留标题层级与页码）→ 切块 → 建索引（默认关键词检索 BM25/FTS5；可选向量检索，Embedding 走 .env 配置的 OpenAI 兼容接口）。
- 文档可关联到产品；检索可限定产品范围。
- 回答流程：弹幕问题 → 意图识别 → 检索 top-k → LLM 依据资料生成口语回答（限字数、**不编造**、资料没有就引导看商品详情或客服）→ 合规过滤 → 播报。
- Web 提供"检索测试 / 回答测试"（只出文字不开口，或勾选直接让数字人说）。

**验收**：用 `tests/fixtures/` 样例文档，问"价格/保质期/尺码"等问题能检索到正确段落；资料没有的问题不胡编；上传/删除/重建索引在 Web 可用。

## R6 产品介绍（讲品）

- 产品库：名称、价格/机制、卖点、讲解稿（分段）、关联文档、关联视频、上架状态。
- 讲解稿可由 LLM 基于知识库一键生成，人工在 Web 编辑后保存；生成结果经合规过滤。
- 主持人在空闲时按"当前产品"的讲解稿逐段播讲，可设置轮播顺序与每个产品讲解时长；有高优先级互动时先互动、再接着讲（断点续讲）。

**验收**：设置两个产品轮播，无弹幕时数字人按讲解稿连续讲；插入礼物/提问后先回应再续讲；在 Web 切换当前产品立即生效。

## R7 视频介绍（后期会投流到直播间）

- 视频素材库：上传 mp4、预览、关联产品、标签。
- 直播画面支持播放产品视频：全屏、画中画（数字人缩小在角落）或分屏；视频原声或静音（静音时数字人可配解说）。
- 可手动"立即播放"，也可按讲品流程自动插播（如讲到某产品时播它的视频）。
- 设计上为"投流"预留：投流带来的人数猛涨由 R2 的 `viewer_surge` 承接；视频播放命令走统一的场景状态接口，以后可接定时任务或外部系统。

**验收**：场景页（OBS 浏览器源）能按命令播放视频、切换布局，播放结束自动回到数字人；视频播放期间数字人不断流（空闲生成照常）。

## R8 Web UI 整齐明了

- 按功能分页：直播控制台 / 弹幕互动 / 产品与知识库 / 视频素材 / 直播间设置 / 数字人与系统 / 离线视频（线框见 05）。
- 统一的布局、配色（亮/暗）、表单与表格样式；状态用徽章；危险操作二次确认；窄屏可用。
- 设置页由后端下发的 schema 自动生成表单（字段说明、范围、是否热更新）。

**验收**：每个功能都能在 Web 完成，不需要命令行；1366×768 与手机宽度下无横向溢出。

## R9 直播间参数 Web 设置 + 热更新

- 设置中心：默认值（代码）→ `live/configs/*.yaml` → 运行时覆盖 `live_data/settings.json`（Web 写入）三层合并。
- 每个设置项标注 `hot`（立即生效）或 `restart`（需重启）；保存时校验类型与范围；保存后通过事件总线通知各模块即时生效。
- 支持导出/导入设置、恢复默认、最近若干版本回滚。
- 密钥类（cookie、API key）在 Web 上只显示"已配置/未配置"，可写入但不回显。

**验收**：修改房间号、回复阈值、人设、音色语速、违禁词、讲品时长等，无需重启即生效（有测试覆盖）；改了 GPU 设备之类的项，页面提示需重启。

## R10 解耦 + 文档同步

- 模块边界、接口签名、事件主题按 03 实现；新增能力（新平台弹幕源、新 TTS、新 LLM、新检索后端）只需新增一个实现并注册。
- 每阶段同步更新 `README_LIVE.md`、`docs/live/ARCHITECTURE.md`、`API.md`、`DEVELOPMENT.md`。

**验收**：P8 时逐条核对文档描述与代码一致；`DEVELOPMENT.md` 有"新增弹幕平台 / TTS / LLM / 检索后端"的扩展示例。

## 不做的事（本阶段非目标）

- 不做其他平台弹幕（快手/视频号）的实现，只留接口。
- 不做服务端视频合成后直接 RTMP 推流（画面合成在场景页，由 OBS 采集；服务端合成留作后续）。
- 不做自动下单、私信、发弹幕等**写操作**（只读直播间消息）。
- 不做扫描版 PDF 的 OCR。
- 不改数字人推理（FlashHead）本身。
